# Benchmark Results & Statistical Reconstruction

This directory contains the complete raw experimental dataset and analysis code for the Phase 2 benchmark.

## Files

- `raw_trials.json`: Machine-readable trial dataset containing all 15 individual test runs (5 per architecture) with request counts, goodput, latency percentiles, compute times, and transit breakdowns. Reconciled total requests: **22,508 requests**.
- `raw_trials.csv`: Standard tabular CSV version of the 15 trials.
- `summary_report.md`: Markdown summary tables generated by `analyze.py`.
- `analyze.py`: Python analysis script that reconstructs the statistical summary tables, Student's t 95% confidence intervals for the mean, non-parametric median metrics, and hypothesis evaluations directly from the raw data.

## Running the Analysis

```bash
# From repository root:
python results/analyze.py

# Or from this directory:
cd results && python analyze.py
```

## Statistical Methodology

1. **Trial-Level Independence:**
   Because requests within an individual load test trial exhibit autocorrelation (shared TCP connection keep-alives, OS socket buffers, worker cache state), treated samples are the **5 independent trial percentile estimates** $(p^{(1)}, p^{(2)}, p^{(3)}, p^{(4)}, p^{(5)})$, rather than individual request timestamps.

2. **Reporting Both Parametric and Non-Parametric Statistics:**
   - **Non-Parametric:** We report the trial **Median**, Interquartile Range (**IQR**), and empirical range $[\text{Min}, \text{Max}]$.
   - **Parametric:** We compute the Student's t 95% Confidence Interval for the trial-level **mean** ($df = 4, t_{0.025, 4} = 2.776$):
     $$\text{CI}_{95} = \bar{p} \pm 2.776 \times \frac{s}{\sqrt{5}}$$
     This interval is reported strictly alongside the sample mean to avoid conflating mean confidence bounds with sample medians.

3. **Reconciled Request Accounting (22,508 Total Requests):**
   Nominal matrix total: $15 \times 1,500 = 22,500$ requests.
   Due to k6 `constant-arrival-rate` microsecond boundary ticks during the final millisecond before stage exit, 8 trials emitted 1,501 requests:
   - Direct Serving: 4 trials @ 1,500 + 1 trial @ 1,501 = **7,501 requests**
   - Ray Python Proxy: 2 trials @ 1,500 + 3 trials @ 1,501 = **7,503 requests**
   - Ray Worker HAProxy: 1 trial @ 1,500 + 4 trials @ 1,501 = **7,504 requests**
   - **Total:** $7,501 + 7,503 + 7,504 = \mathbf{22,508\text{ requests}}$

4. **Raw Data Limits & p99 Interpretation:**
   - Data consists of trial-level percentile summaries generated by k6; individual per-request timestamp traces were not persisted to disk.
   - Each trial ran for 30s at 50 req/s (~1,500 requests). In a 1,500-request sample, the p99 percentile reflects approximately the 15 highest-latency requests.
   - Across 5 trials, isolated scheduling events or GC pauses can heavily inflate p99 variance (as observed in Trial 4 of the Python Proxy). Tail measurements should be understood as sensitivity indicators under micro-bursts rather than steady-state upper bounds.
